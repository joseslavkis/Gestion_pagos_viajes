# Payment attachment amounts UI

## Objective and scope
Let a user enter a temporary ARS/USD amount for each of 1–5 selected receipts, inspect per-currency subtotals and a backend-calculated trip-currency total, explicitly confirm that total, and register exactly one PaymentSubmission with the existing multi-file upload. Preserve the backend schema, DTOs, review/approval/void/allocation and admin UI. `paymentMethod` and `bankAccountId` remain global. No commits, push, PR, merge or deploy per this request.

## Problem and constraints
Files currently have no per-file amount context. Monetary inputs must stay decimal strings (never `parseFloat` to prepare commands); use the existing calculation endpoint for cross-currency equivalence, not a frontend FX rule. Auxiliary preview tokens must never authorize registration. Stale async results and changed receipts must never preserve confirmation or registration authority. Preserve existing untracked files.

## Acceptance and checks
Per-file data never enters the POST. Sum same-currency values exactly in decimal strings; cross-currency equivalence comes from the existing backend MANUAL calculation, with display-only auxiliary tokens. Final calculation uses `paymentCurrency = tripCurrency` and the full total, then registration uses only its current READY previewToken. A change of amount/currency/files synchronously revokes confirmation. Submission needs valid files, all positive cent-precision amounts, no file error, current computed total, explicit confirmation, and current final READY/token. Tests: `npm test -- src/features/users/pages/__tests__/UserDashboardPage.test.tsx` (plus focused helper tests), `npm test`, `npm run build`, `npm run lint` from `frontend/`.
